RAG RAG 笔记：从一次检索失败开始 用一条失败样例检查数据、召回和生成。

当 RAG 给出错误答案，先选一条能稳定复现的问题。把原始问题、预期答案、能够支持答案的原文和系统实际输出放在一起，就能逐步定位信息在哪里丢失。

  1. 检查数据。在索引里找到预期段落，确认正文已被提取，切分后仍保留条件、单位和例外条款。
  2. 检查召回和排序。查看召回候选，再查看重排后实际交给模型的片段。候选中缺少证据时，检查过滤条件、关键词或向量检索。证据在重排后消失时，检查排序和上下文预算。
  3. 检查生成。把正确段落单独提供给模型，对照回答和原文。记录遗漏、误读和无法支持的断言。

修复后用同一条问题再跑一遍，并保留输入、候选片段和输出。再复查几个原本能答对的问题，确认改动没有破坏已有表现。
